⚠️ Fever Threshold Sensitivity & Risk Notice

Calibration Output Compression Risk: The fitted dataset regression formula (slope = 0.2508) compresses output values into a narrow band near the low-grade fever threshold (37.5°C). Any skin reading above 36.65°C maps above 37.50°C. With R² = 0.19 on the source dataset, this causes a systematic bias toward false positive fever flags. This calibration requires validation across multiple distinct subjects (including known normal and febrile controls) before relying on it for screening.

📋 Project Overview

Contactless Thermal Vital Signs Monitoring System — an end-to-end computer vision + machine learning application that processes thermal imagery and video to monitor body temperature / fever and respiratory rate without physical patient contact, backed by a local Flask API and this interactive dashboard.

  │    ├─ Dynamic face/neck masking → contour detection
  │    ├─ Forehead ROI (5-22% H, 25-75% W) + Inner Canthus ROI
  │    ├─ Pixel intensity → skin temp → oral/core calibration (UCI dataset)
  │    └─► Fever Status (Normal / Low-Grade / Moderate / High)
  │

  │    ├─ MediaPipe Face Mesh → nasal ROI (landmarks 4 & 13)
  │    ├─ Frame-by-frame mean intensity → Z-score normalize
  │    ├─ Butterworth bandpass filter (0.1–0.5 Hz = 6–30 bpm)
  │    └─► Signal RR (peak detection + interval timing)
  │
  ├─► 🆕 Multi-Method Analysis (rr_signal_methods.py)
  │    ├─ 🔍 Peak Detection — time-domain peak counting
  │    ├─ 🔄 Autocorrelation — periodicity via self-correlation
  │    ├─ 📊 Welch PSD — averaged power spectral density
  │    ├─ 🌊 CWT — continuous wavelet transform (Morlet)
  │    └─► 🤝 Consensus (median of successful methods)
  │
  ├─► ML Models (rr_model.py)
  │    ├─ Random Forest / Gradient Boosting / XGBoost / Ensemble
  │    └─ Trained on 6 features from 32 labelled thermal videos
  │
  └─► Status Flagger (status_flagger.py)
        ├─ Temp: Hypothermia / Normal / Low-Grade / Moderate / High Fever
        ├─ RR: Bradypnea (<12) / Normal (12-20) / Tachypnea (>20)
        └─► Combined triage flag + action recommendation

🆕 New Signal Analysis Methods — What Changed & Why

🔍 Peak Detection

What: Counts breathing peaks in the filtered signal using adaptive prominence thresholds.
How it helps: Provides a direct, interpretable breath count. Compared against the existing peak detector to validate consistency. Confidence is based on number of detected peaks.

🔄 Autocorrelation

What: Measures signal self-similarity at different time lags to find the dominant periodic cycle.
How it helps: Robust to irregular peak shapes and noise — detects periodicity even when individual peaks are ambiguous. Reports correlation strength as a natural confidence metric.

📊 Welch PSD (Power Spectral Density)

What: Averages FFT over overlapping segments (Welch's method) to estimate the power spectrum more reliably than a single raw FFT.
How it helps: Reduces spectral noise variance. The band power ratio (breathing band vs. total) directly measures signal quality. More stable than the existing single-shot FFT in rr_model.py.

🌊 CWT (Continuous Wavelet Transform)

What: Applies a Morlet wavelet transform to analyze frequency content with time-frequency resolution.
How it helps: Captures non-stationary breathing patterns (varying rate over time) that fixed-window FFT methods miss. Requires PyWavelets; degrades gracefully if not installed.

🤝 Multi-Method Consensus

What: Takes the median of all successful methods' BPM estimates.
How it helps: A single method can fail or be biased by noise. The consensus combines independent estimation approaches — if they agree (spread < 3 bpm), confidence is high; if they somewhat agree (spread < 5 bpm), confidence is medium; otherwise low. This gives a more trustworthy estimate than any single method alone.
